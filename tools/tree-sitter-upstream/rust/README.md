Entmoot crate pin: **0.24.2** (Cargo.lock is authoritative).
Pinned upstream revision: `77a3747266f4d621d0757825e6b11edcbf991ca5`.
[baseline.json](baseline.json) records the October 10, 2026 profile. This packet
qualifies existing grammar behavior; it proposes no syntax patch and makes no
production native-provider or upstream-acceptance claim.

The lock pins generator **0.26.7** (declaration `^0.26.7`); measured parser ABI is
**15**. Upstream tracks generated C/JSON. Two generations match on each platform,
and generated bytes match between Windows and Linux. The tracked parser's release
metadata says 0.24.1 while the package and `tree-sitter.json` say 0.24.2.
Regeneration changes only that metadata integer; grammar JSON, node types, 3,825
states and 351 symbols remain unchanged. Both complete 151-group corpus runs pass.
The [receipt](qualification_2026-10-10.json) retains this mismatch explicitly.

The upstream platform matrix is Windows, Linux and macOS. Its CI explicitly
enables Rust, Python, Go and Swift bindings and disables Node tests, although
binding metadata includes Node. Shared runners now support that explicit
disablement without skipping lint or reporting Node as tested. A C# regression
control verifies that Node bindings still run by default. Node 22.23.3 supplies
the locked lint tooling; it is not a Rust runtime. The Linux CLI is a local build
of the exact published, locked 0.26.7 crate using Rust 1.95.0.

The upstream Cargo lock also records root package 0.24.1, causing the original
`cargo test --locked` lane to fail. Cargo's scratch-only correction changes that
one version to 0.24.2 and no dependency bytes. [build-locks/Cargo.lock](build-locks/Cargo.lock)
retains the generated result; [prepare_bindings.py](prepare_bindings.py) verifies
its exact scope against the original Git object before applying it. The initial
offline build additionally reported missing cached `cc 1.2.57`; the qualified
locked build downloads that exact pin. Foreign sources remain untouched.

With that correction, Linux Rust, Go, Python, lint and CMake checks pass. Windows
Rust, Python, lint and CMake pass; Windows CGo fails because GCC is absent. Node
bindings are upstream-disabled, Swift/macOS are unrun, and no WebAssembly
execution is qualified. These are upstream binding smoke tests, not Entmoot
semantic-resolution or whole-platform completeness claims.

[Authored controls](cases.py) and the [executable oracle](qualify_features.py)
separate CST parsing, compiler/edition acceptance and actual execution. All 34
controls pass, including 24 executed programs. Actual Linux rustc 1.99.0 compiles
C and C-unwind variadic definitions across editions 2015, 2018, 2021 and 2024;
the existing 1.95.0 compiler rejects the new definition feature. Historical
controls use 1.95.0 explicitly. These are not an exhaustive old-compiler matrix.

The [Rust 1.99 release](https://blog.rust-lang.org/2026/10/01/Rust-1.99.0/)
stabilizes these definitions and the associated variable-argument API. The
compiler controls independently exercise fixed and ignored parameters, missing
patterns, wrong ABI, required unsafe declarations, non-final variadics and
argument promotion. The grammar accepts several compiler-rejected forms; that
does not establish a legal call or a bind. An unnamed `...` is valid in the
historical external declaration control but the new function definition requires
a pattern. Compiler evidence determines that distinction, not the CST.

Further controls retain methods, async blocks, const generics, let-else, let
chains, inline const, C-string literals, raw pointer borrows, async closures,
raw/contextual `gen` identifiers, macros, Unicode/CRLF coordinates and malformed
syntax followed by a sibling declaration. Explicit selectors check node kinds,
fields and byte spans. Every valid parse undergoes incremental damage/repair
against a fresh full-node/field/span parse. Async futures deliberately dropped
without polling receive compiler qualification, not a claim that their body ran.
Tokens inside an outer macro invocation remain opaque; the macro fixture selects
a directly visible invocation and does not invent a nested call from token text.

[Example qualification](qualify_examples.py) streams 1,858 regular Rust Git
objects and 17,882,577 bytes from the grammar's own examples plus bitflags, libc,
regex, serde and tokio. Tracked and regenerated parsers produce identical named
CSTs. Both retain two errors, exactly the two matched libc workflow exclusions;
all 1,856 workflow-included files parse without errors. Excluded inputs are still
parsed and counted, not hidden. No foreign example is compiled or executed:
edition acceptance, conditional compilation and macro expansion remain unknown
outside the independent feature controls.

The generated C is 6,505,510 bytes and both Windows libraries are 1,121,280 bytes.
Five fresh-parser and five unchanged-tree samples over four pinned files preserve
identical CSTs; all eight sample ranges overlap. This metadata-only comparison
is a baseline, not a syntax fix or an optimization. It makes no OS cold-cache,
pipeline/storage, process-tree memory or capacity claim.

Reproduce with fresh scratch directories and receipt names:

```text
python tools/tree-sitter-upstream/materialize_baseline.py --profile tools/tree-sitter-upstream/rust/baseline.json --grammar <fresh-grammar> --cli <0.26.7-cli> --receipt <build.json>
python tools/tree-sitter-upstream/rust/prepare_bindings.py --grammar <fresh-grammar> --receipt <preparation.json>
python tools/tree-sitter-upstream/rust/qualify_features.py --grammar <linux-rust-library> --toolchains <isolated-rustup-toolchains> --out <fresh-feature-output>
python tools/tree-sitter-upstream/rust/qualify_examples.py --tracked <tracked-library> --regenerated <regenerated-library> --out <fresh-example-output>
python tools/tree-sitter-upstream/measure_parser.py --language rust --baseline <tracked-library> --candidate <regenerated-library> --out <fresh-measurement.json>
```

The feature driver is a Linux lane. It calls actual pinned compiler binaries,
removes `RUSTC_BOOTSTRAP`, supplies explicit editions and records compiler,
driver-library and standard-library digests. No unstable feature gate is enabled.
Materializations use unique `TREE_SITTER_LIBDIR` caches, retain tracked and
regenerated libraries separately, and append scratch Cargo workspace isolation.
Binding runners must use `--skip-node-tests` for this upstream profile. No compiler
or package installation enters the default structural build path.

No patch/fork is adopted by this record. Any temporary adoption must be removed
when upstream supplies qualified equivalent behavior, or reassessed at dependency
updates and the repository move. Maintainer acceptance is an external outcome.
Remove the retained root-version lock correction when upstream release metadata
agrees; do not keep it as a permanent compatibility shim.
