# tree-sitter-c

Upstream: <https://github.com/tree-sitter/tree-sitter-c>. License: MIT.
Entmoot crate pin: **0.24.2** (Cargo.lock is authoritative). Baseline source:
`b780e47fc780ddc8da13afa35a3f4ed5c157823d`. The
[retained packet](qualification_2026-10-10.json) qualifies local candidate
grammars at the October 10, 2026 cutoff; no production adoption is implied.

The baseline locks CLI **0.25.4** (declaration `^0.25`); measured ABI is **15**.
Regeneration changes only the generated C header comment. Its complete 85-group
corpus passes. [PR #331](modern-types/README.md) pins source
`0e6495284f5b1b43d5fff00ad1903e8bad90d350`; its checked-in generated sources
match CLI **0.26.13**. The composed candidate adds
[atomic types](atomic-types/README.md), [trailing labels](trailing-labels/README.md)
and [historical identifiers](historical-identifiers/README.md). All 120 upstream
corpus groups pass on Windows and Linux, two generations repeat exactly, and
generated source bytes agree across platforms. Upstream tracks generated C/JSON;
submit regenerated files according to its policy, never a vendored repository.

The official Linux 0.26.13 binary requires GLIBC 2.39 and does not run on the
Ubuntu 22.04 host. A local build of the exact locked published CLI crate with
Rust 1.95.0 produces the same generated bytes. The downloaded old 0.25.4 assets
have no published asset digest: the receipt records local digests and HTTPS
provenance without claiming independent upstream digest verification.

The upstream platform matrix is Windows/Linux/macOS; only Rust binding tests
are enabled in CI. Qualified Linux Rust, Python, Go, actual Go parser installation,
lint and CMake lanes pass. Windows passes the available lanes; CGo fails because
GCC is absent. Python/Go/CMake checks supplement C's enabled CI scope. Node is
upstream-disabled; macOS, Swift and WebAssembly execution are unrun.
[Build metadata](build-metadata/README.md) records original npm, Python, CMake
and Go failures separately from their qualified repairs. A failed CMake build
that removes generated files now leaves an explicit failed receipt, verified
against the original recipe.

No grammar-specific CONTRIBUTING/AGENTS file was present in the inspected original
repository. Review its README, package scripts and .github/workflows again before
human submission. Core's maintainer-only contribution rule is separately scoped in
the [parent record](../README.md); it is not automatically a rule for this grammar.

The [authored cases](cases.py) and [feature oracle](qualify_features.py) separate
CST expectations, explicit compiler modes and execution. Actual Clang **23.1.3**
meets all 68 acceptance/rejection expectations; all 58 eligible programs execute.
The composed parser meets 68/68 CST expectations, versus 33 baseline and 43 for
PR #331 alone. All 67 error-free candidate trees pass incremental damage/repair
parity; the malformed-sibling control remains an explicit error tree with its
following function preserved. Byte/point spans, declaration/identifier fields
and following definitions are selected explicitly. Group `fixtures.json` files
reference these shared authored fixtures and are validated by the runner and packet builder;
they do not duplicate or generate expected results from parser output.

C89/C99/C11/C17 historical controls remain separate from C23 and draft C2y.
[GCC 11.4 controls](qualify_historical.py) additionally qualify older syntax with
an actual historical compiler. Across C and experimental C++, all 46 checks and
43 executions pass. Current compiler modes do not prove all historical versions.
C23's generic type-operand negative and C2y's positive are reported separately.
Provider coordinates, macros, includes and typed dispatch are not semantic
claims of a grammar parse. [WG14](https://open-std.org/jtc1/sc22/wg14/www/projects.html)
and [Clang's status](https://clang.llvm.org/c_status.html) provide standards context;
actual compiler receipts determine these fixture results. Broad GNU/MS/escape
changes in PR #331 lack separate compiler qualification here.

[All upstream examples](qualify_examples.py) stream three regular Git objects,
273,251 bytes, selected by literal `examples/*`; there are no workflow exclusions.
All variants have zero errors and identical named CSTs. Foreign examples are
neither compiled nor executed. This small example scope is not a scale campaign.
The composed C parser grows from 3,872,012 to 4,973,291 C-source bytes and from
624,128 to 870,912 Windows library bytes (2,015→2,374 states). Five fresh-parser
and five unchanged-tree samples over each example have overlapping ranges in
all six comparisons. This establishes neither an optimization nor pipeline,
storage, OS cold-cache or process-memory performance.

Experimental C++ retains its own **C 0.24.1** grammar dependency. Substituting
the C composition fails generation because C++ overrides the required conflicts;
that failure is retained. No C grammar change silently propagates to C++.

The feature/historical drivers use the recorded WSL Ubuntu compiler environment
on Windows. Add `--selection <change/fixtures.json>` for one coupled feature group.
The default candidate is `composed`; `--candidate <variant>` selects another
variant. Candidate success, completed comparison and baseline gaps are separate.
Binding runners use `--skip-node-tests` and the explicit Go oracle;
all tools belong to this qualification lane. The default structural build does
not install or invoke a language compiler or grammar generator.

No patch/fork is adopted by this record. Any temporary adoption must be removed
when upstream supplies qualified equivalent behavior, or reassessed at dependency
updates and the repository move. Maintainer acceptance is an external outcome.
